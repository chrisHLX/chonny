# CC-immunity curation for spells whose immunity has NO structured source anywhere in this
# pipeline. See the 2026_09_07 migration's docblock for the full measured rationale; the short
# version, re-verified 2026-09-07:
#
#   - 220 of 250 PvP talents have ZERO spell_effects rows, so ccImmunityGrantedBy() has nothing
#     to read. 0 of those 220 appear in the raw SimC dumps at all (checked against all 12,468
#     `Name : X (id=N)` records) - SimC genuinely does not ship PvP talent spells; this is not
#     regenerate-filtered.php dropping them. Only 10 of 220 have a same-name sibling with effects.
#   - Blizzard's own /data/wow/spell/{id} was called live and returns id/name/description/media
#     only. There is no official structured source to import. The free-text description IS the
#     source of truth, and it has to be hand-read - one verified line at a time, same discipline
#     as baseline-spec-overrides.txt and cc-synergies-overrides.txt.
#
# FORMAT (4 fields):  spell_id | mechanics | gating_spell_id | note
#
#   spell_id         EXTERNAL Blizzard spell_id (matches spells.spell_id) of the spell a player
#                    actually PRESSES. For the dominant "passive PvP talent modifies a base
#                    ability" shape, that is the base ability, NOT the talent - a player looking
#                    for this fact is looking at the ability's card. Pick the copy the site really
#                    renders (cross-check data/spell-kits/{class}/{spec}.json), not just any
#                    same-named record.
#
#   mechanics        Comma-separated mechanic names from
#                    ModuleSpellReferenceService::MECHANIC_IMMUNITY_CODE_MAP - exactly one of
#                    Stun, Silence, Incapacitate, Fear, Interrupt, Sap. Validated at import;
#                    anything else is warned about and the line skipped, never stored.
#
#                    THERE IS NO WILDCARD, deliberately. Blizzard's text carries real carve-outs
#                    (Phase Shift avoids all attacks and spells but explicitly NOT interrupts), so
#                    an "all CC" value would silently over-claim. List every mechanic explicitly.
#
#                    Only Stun / Silence / Incapacitate currently generate counter rows - those
#                    are the three DR categories SpellCounterIndexer maps by exact name. Fear and
#                    Interrupt are still worth recording: they display on the spell card, and they
#                    are already correct if that map is ever widened. See the note at the bottom.
#
#   gating_spell_id  EXTERNAL spell_id of the PvP talent that must be selected for the immunity to
#                    exist at all. Leave EMPTY when the listed spell grants it on its own.
#                    External, not the internal PK, for the same reason
#                    conditional_dr_gating_spell_id is: it is what this file states, what the
#                    description names, and what survives a re-import unchanged.
#
#   note             Free text, last field, may contain anything except a literal pipe character.
#                    State which talent is required and any carve-out, since the base ability
#                    alone does NOT have this behaviour.
#
# Every line below was read off the gating talent's own in-game description text, quoted in the
# note. Nothing here is inferred from a name or assumed from similar-looking entries.

# --- Known gap, flagged not fixed -------------------------------------------------------------
# SpellCounterIndexer::DR_CATEGORY_TO_IMMUNITY_MECHANIC maps only Stun/Silence/Incapacitate, so a
# Fear immunity curated above does not yet produce a counter row against a Disorient-category CC.
# Blizzard's "Fear" mechanic and this project's "Disorient" DR category do describe the same real
# thing, so that mapping is probably correct to add - but it would change existing counter output
# for every spell, not just these, so it belongs in its own reviewed change rather than riding
# along with this one.
