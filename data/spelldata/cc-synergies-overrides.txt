# Synergies tab curation — dr_category / chain_target / is_peel / is_interrupt /
# pvp_duration_seconds / pairs_with_category / requires_stealth / requires_target_out_of_combat.
#
# WHY THIS FILE EXISTS: every one of these eight columns is manual_knowledge-tier, hand-curated
# by the domain expert (or bulk-applied from dr-categories-reference.md and individually
# verified) — none of it is derivable from the raw SimC/Game-Data-API dumps, and this project
# has repeatedly proven that trying to derive it is exactly the "AI invents a fact and presents
# it as ground truth" failure mode that keeps having to be caught and reverted (Mind Sear,
# alwaysAvailableAbilityIds(), spells.mechanic disagreeing with real dr_category on 2 of 4
# spot-checks — see CLAUDE.md's "Synergies tab" and "chain_target rule articulated" sections for
# the full history). Found missing 2026-08-11 the same way the baseline-spec-overrides.txt gap
# was originally found: a real deploy (migrate + import:spelldata on production) produced an
# empty Synergies tab, because every one of these columns had only ever been written
# directly to the local dev DB via one-off scripts during the session that built the feature —
# never captured into a version-controlled file. This file is that capture, generated once by
# dumping the dev DB's full curated state, and is now the SOURCE OF TRUTH going forward — any
# future dr_category/chain_target/is_peel/is_interrupt/pvp_duration_seconds/pairs_with_category
# change must be added here, not just written to a local DB, or it will silently vanish on the
# next fresh import anywhere else (exactly the failure this file exists to prevent from recurring).
#
# SECOND INCIDENT, 2026-08-23: a batch of ~18 real, already-DB-applied entries (mostly the
# 2026-08-22 "cast/display copy has no real aura, sibling does" sibling-recovery fixes) had been
# written to the working-tree copy of this file but never committed. A later accidental
# `git checkout -- <this file>` (meant only to undo a same-session scripting bug) silently
# discarded that uncommitted work from the FILE — the live DB was untouched (upsertTrack() never
# got a chance to overwrite it, since the broken script made every affected line fail validation
# and skip), so nothing on the actual site broke, but the file briefly stopped matching the DB it's
# supposed to be the source of truth for. Recovered the same day by diffing DB state against the
# file to find every spell_id with curated data but no file line, and writing each back in from
# the DB's own values (commentary reconstructed from this project's own committed documentation
# of those same fixes elsewhere, where available — flagged plainly where it wasn't). Lesson: this
# file must be committed promptly after each curation session, not left as an accumulating
# uncommitted diff — and `git checkout`/`git reset` on it should never be reached for without
# first diffing against HEAD to see what's actually at stake.
#
# Format: spell_id | dr_category | chain_target | is_peel | is_interrupt | pvp_duration_seconds | pairs_with_category | requires_stealth | requires_target_out_of_combat | name (comment only, not parsed)
#   - dr_category: Stun | Disorient | Incapacitate | Root | Silence | Knockback | Disarm | Slow, or blank
#   - chain_target: healer | kill_target | both, or blank. STANDING RULE (see
#     CcChainBuilder's class docblock): kill_target/both may ONLY ever be used with
#     dr_category = Stun or Silence (CC that doesn't break on damage) — everything else
#     (Incapacitate/Disorient/Root/Knockback/Disarm/Slow) can only ever be healer or blank.
#   - is_peel / is_interrupt: "1" or blank.
#   - pvp_duration_seconds: a decimal (e.g. "6.0"), or blank. Real, per-spell confirmed PvP
#     duration — NEVER derived from spells.duration_seconds (confirmed unreliable/PvE-scoped
#     dataset-wide, see CLAUDE.md's "PvP CC duration cap" section).
#   - pairs_with_category: another dr_category value (currently only ever "Root"), or blank.
#     Added 2026-08-23 for wow:cc-formula. Means "this spell's effect structurally depends on a
#     CC of the named category landing on the same target around the same time" — e.g. Solar
#     Beam/Ring of Frost are stationary ground-zone effects ("enemies entering the ring are
#     incapacitated" / "silencing all enemies within the beam") that a mobile target can simply
#     walk out of, so real play pairs them with an instant Root to hold the target in place.
#     Verify via the spell's own description text (does it name a location/zone/ring rather than
#     applying directly to the target?) plus, ideally, a real co-occurrence check in the arena-log
#     archive — never guess this from statistical co-occurrence alone, since two abilities being
#     used near each other in logs doesn't distinguish "structurally required" from "often chosen
#     together for unrelated reasons" (the same caution that sank spell_relationships as a
#     spec-attribution signal elsewhere in this project).
#   - requires_stealth: "1" or blank. The caster must be stealthed to use this ability at all
#     (e.g. Sap, Rake's stealth-stun component). Added 2026-08-23 for wow:cc-formula, so it can
#     eventually distinguish a "stealth opener" chain from abilities usable mid-fight.
#   - requires_target_out_of_combat: "1" or blank. The TARGET must not have dealt damage or
#     received healing for the preceding ~5 seconds (WoW's real in-combat gate) — distinct from
#     requires_stealth, since it's a condition on the target, not the caster. Sap needs both;
#     Rake's stealth-stun needs only requires_stealth, since it has no target-combat-state gate.
#     Direct domain-expert correction, 2026-08-23 — verify against real player knowledge, not
#     assumed from "loses stealth" reasoning alone.
#
# Matched by spell_id only (not class/spec) — these are properties of the spell/ability itself,
# not of who has it. Applied via a plain UPDATE against an existing spells row for the current
# patch; a spell_id not present in the current patch's data is skipped and warned about, never
# guessed at or auto-created.
#
# Adding or changing a line here is a real claim about the live game, not a data-cleanup nit —
# verify it (in-game, real player experience, or a source cross-checked with the domain expert)
# before adding, same discipline as baseline-spec-overrides.txt.
